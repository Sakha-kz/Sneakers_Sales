# NorthX — как создать администратора и войти в магазин

Эта инструкция для владельца магазина. Создать сотрудника можно после подключения Supabase по [NORTHX-SETUP.md](NORTHX-SETUP.md).

У администратора есть две отдельные вещи: **учётная запись с email и паролем** и **разрешение управлять магазином**. Нужно выполнить оба шага ниже. Регистрации на сайте для покупателей нет.

## 1. Откройте свой проект Supabase

1. Зайдите на [supabase.com/dashboard](https://supabase.com/dashboard).
2. Войдите в аккаунт владельца проекта и выберите проект NorthX.
3. Проверьте, что миграции `001_northx.sql` и `002_validate_catalog.sql` уже выполнены. Если ещё нет — сначала выполните настройку из NORTHX-SETUP.md.

Аккаунт владельца Supabase и аккаунт администратора сайта — разные учётные записи. Сотруднику магазина не требуется доступ к панели Supabase.

## 2. Зарегистрируйте администратора

1. В проекте откройте **Authentication → Users**.
2. Нажмите **Add user → Create new user** (названия могут немного отличаться в зависимости от языка панели).
3. Укажите email сотрудника и отдельный надёжный пароль. Используйте адрес, который действительно принадлежит сотруднику.
4. При ручном создании включите **Auto Confirm User / подтверждение email**, если этот пункт показан. В этой инструкции создаётся пользователь с готовым паролем, без приглашения по ссылке.
5. Создайте пользователя. Откройте его карточку и скопируйте **User UID / ID** — длинный идентификатор вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`.

Для каждого сотрудника создайте свою учётную запись. Email и пароль сайта не нужно записывать в файлы проекта или пересылать в этот чат.

## 3. Выдайте доступ к магазину

1. Откройте **SQL Editor → New query** в том же проекте Supabase.
2. Вставьте запрос ниже.
3. Замените `ВСТАВЬТЕ_UUID` скопированным ID пользователя, сохранив одинарные кавычки.
4. Нажмите **Run**.

```sql
insert into public.admin_access (user_id)
values ('ВСТАВЬТЕ_UUID')
on conflict do nothing;
```

Если запрос выполнен успешно, права выданы. Повторное выполнение для того же пользователя безопасно. Пароль в SQL вставлять не нужно.

**У всех администраторов одинаковые права:** добавлять и удалять товары, менять цены, фото, описания и наличие, редактировать WhatsApp и адрес. Выдавать другим людям доступ можно через панель Supabase владельца.

## 4. Войдите на сайт

1. Запустите проект: в папке `E:\Sneakers_Sales` выполните `npm run dev`.
2. Откройте [http://localhost:3000/ru/admin](http://localhost:3000/ru/admin).
3. Введите email и пароль, созданные на шаге 2.
4. После входа появятся **Товары**, **Новый кроссовок** и **Настройки магазина**.

Если сайт запущен на другом порту, используйте адрес из окна запуска, добавив `/ru/admin`. На опубликованном сайте адрес будет `https://ВАШ-ДОМЕН/ru/admin`. Есть также `/kk/admin` и `/en/admin`.

`localhost` на телефоне означает сам телефон. Для работы сотрудников с разных устройств нужен опубликованный сайт, подключённый к тому же проекту Supabase.

## 5. Добавьте первый товар

1. Нажмите **Новый кроссовок**.
2. Заполните название на трёх языках, цену и категорию. При необходимости добавьте описания.
3. Выберите фотографии с устройства, перетащите их в форму или снимите фото камерой. Допустимы JPEG, PNG, WebP, до 5 МБ; максимум 8 снимков.
4. Нажмите **Главное фото** под снимком, который должен показываться первым.
5. Выберите размеры 36–46 и укажите наличие.
6. Нажмите **Сохранить** и дождитесь уведомления **Товар сохранён**.
7. В настройках магазина сохраните настоящий номер WhatsApp с кодом страны и адрес. Без номера оформить заказ через WhatsApp нельзя.

Проверьте витрину на другом устройстве: товар должен появиться после сохранения. При недоступности Realtime предусмотрена резервная проверка каждые 15 секунд в открытой вкладке.

## Как добавить следующего администратора

Повторите шаги **2 и 3** для нового email. Повторно создавать базу, применять миграции или менять `.env.local` не нужно.

## Как проверить список администраторов

В SQL Editor выполните:

```sql
select users.email, access.user_id
from public.admin_access as access
join auth.users as users on users.id = access.user_id
order by users.email;
```

Этот список предназначен для владельца проекта; публичная витрина его не показывает.

## Как забрать доступ у сотрудника

Скопируйте ID нужного сотрудника и выполните в SQL Editor:

```sql
delete from public.admin_access
where user_id = 'ВСТАВЬТЕ_UUID';
```

После этого новые запросы на изменение товаров, настроек и файлов будут отклоняться, даже если сотрудник ещё не вышел из аккаунта. Уже отправленную операцию это не отменяет. Товары магазина сохраняются. Не удаляйте собственный доступ случайно.

При необходимости учётную запись сотрудника можно затем удалить в Authentication → Users. Для прекращения доступа к магазину достаточно удалить запись из `admin_access`.

## Если войти не получается

| Что видно | Что проверить |
| --- | --- |
| Кнопка «Войти» неактивна, показано сообщение о Supabase | Заполните `.env.local` по NORTHX-SETUP.md и перезапустите сайт. Для опубликованного сайта переменные задают перед новой сборкой. |
| «Неверный вход или нет прав администратора» | Email и пароль, подтверждение email в Auth, наличие UUID в `admin_access`. Пользователь и таблица должны быть в одном проекте Supabase. |
| `invalid input syntax for type uuid` в SQL Editor | Вместо UUID оставлен текст-заглушка, вставлен email или скопирован неполный ID. |
| Ошибка внешнего ключа при выдаче доступа | Такой ID не найден в Auth этого проекта. Создайте пользователя в Authentication → Users и скопируйте его ID заново. |
| Вход работает, но товар не сохраняется | Проверьте соединение, заполненные названия, размеры, фото и применение обеих миграций. |
| Забыт пароль | В текущем сайте нет страницы автоматического восстановления пароля. Владелец проекта может создать новую учётную запись с доступным email, выдать ей права и отозвать доступ старой. |

В настройках Auth оставьте публичную регистрацию выключенной. В `.env.local` используется только публичный anon/publishable key; секретный `service_role` / secret key в сайт не добавляют.

Справка Supabase: [управление пользователями](https://supabase.com/docs/guides/auth/managing-user-data), [вход по паролю](https://supabase.com/docs/guides/auth/passwords).
